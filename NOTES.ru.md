# Объяснение текущей структуры проекта и особенностей модулей

Теперь (v1.0.0) у нас есть 3 компонента ассистов:

### — MCA Core (src/core)
Основная часть ассистов, не зависящая от других модулей MCA. Царь-батюшка, управляющий всем приложением. Центр.
В нём можно выделить 3 компонента:

**№1. Brain :: Мозг**. Основная структура, запускающая другие (№2,3). Функции:
  - взаимодействие с ботом Mineflayer
  - управление очередью задач (и самими задачами)
  - управление приложением (и его глобальным состоянием) в целом; Например, отправка предупреждений в консоль или закрытие процесса

**№2. ResourceManager :: Менеджер ресурсов (ассетов, хранилищ, состояний и т.д.)**. По факту, изолированная база данных с доп.логикой и фичами, а также хранилище состояния (например: список загруженных навыков)

**№3. SkillsHandler :: Обработчик навыков**. В новой версии файлы навыков лежат отдельно от всего остального кода ((об этом - далее)), и эта структура занимается их загрузкой и обработкой.
Функции:
  - чтение папки с навыками (и её поверхностных файлов)
  - контейнеризация навыков (запуск их в песочнице). ЗАМЕЧАНИЕ: Пока-что используется "плохая", незащищённая песочница. Но позже мы это починим. ((это отдельная тема))
  - загрузка и запуск файлов с навыками; чтение и проверка (прим.: проверки пока нет) манифеста
  - предоставление ограниченного (!) API для взаимодействия с "внешним миром" ((об этом - далее)).
---

### — MCA Official Skills Collection (src/skills).
По факту, отдельный проект. В будущем рассматриваю возможность вынесения в отдельную репу (хотя не думаю, что это понадобится). Содержит папки с модулями. В папках может быть несколько файлов, но главный должен называться по имени папки.

В счастливом будущем рассматриваю возможность добавления сюда навыков от других разработчиков (то есть официализацию внешних модулей). Примечание: в том же светлом будущем рассматриваю инкрементальную (частичную, выборочную) установку навыков. Рассказ про сжатый онлайн-репозиторий мы пока опустим

Напоминаю, что эти навыки компилируются отдельно от ядра ассистов (со всеми библиотеками) и поставляется пользователю в отдельной папке. Подразумевается, что пользователь может просто "закинуть" в папку новый навык и он: А) гарантированно не причинит вреда его компьютеру (но пока-что контейнеризация не работает), Б) "просто будет работать", без сложных установок: "перекинь в папку и готово".

Некоторые понятия:
- — МАНИФЕСТ навыка: объект, в котором содержится вся информация о навыке: айди, человечное название, версия, автор, интенты и пр.
- — ИНТЕНТЫ это набор полномочий (разрешений) навыка, которые он сам запрашивает у пользователя. ((взято с Android, хах))
- — Ограниченный API. Навыки (скрипты) запускаются в песочнице, и у них есть ряд ограничений. Например, отсутствуют привычные console/process, нет модульности CJS / ESM. Вместо этого, есть глобальная переменная mcaEnv. Она содержит ОКРУЖЕНИЕ НАВЫКА:
  - defineSkill() :: функция, которая должна быть вызвана ПЕРЕД всеми операциями. Принимает на вход манифест. Возвращает промис (поэтому должна быть вызвана с await)
  - checkIntent() :: функция для проверки наличия интента. Пользователь может отказать в предоставлении интента навыку. В таком случае, навык должен сам обработать данный случай.
  - require() :: функция для импорта ядра и ограниченного заранее указанного набора библиотек. Возвращает промис с библиотекой/модулем.
  - loadSkills() :: функция, берущая на вход класс навыка. Она правильно инициализирует класс навыка, передавая ему текущий Brain со всем состоянием бота. Должна быть вызвана в самом конце кода.
  - поля logger (TODO), filepath (реальный путь до текущего файла), skillId (готовый ID навыка: org.mcadev.dtkdtk:auto-eat:1.0.0)

### — Launcher (src/launcher)
Это своеобразный "мостик" между враждебным приложением и пользователем.
В ИДЕАЛЕ:
- Читает, парсит, проверяет конфигурацию, отлавливает ошибки, автоматически отправляет баг-репорты, автоматически исправляет некоторые проблемы, обновляет MCA, позволяет пользователю удобно управлять коллекцией навыков (устанавливать новые, к примеру).
В ДАННЫЙ МОМЕНТ:
- Читает, парсит, проверяет конфигурацию, да с горем пополам запускает единственную инстанцию бота. Multi-bots пока в разработке.

В будущем как раз его я и планирую переписать на GUI.

Он тоже по-своему собирается: он предоставляется пользователю  "как есть" (именно поэтому он написан на JS). Но в будущем это изменится.

## Премудрости сборки

Сборка осуществляется с помощью скрипта `/scripts/build.sh`, в папку `/build/`. Под сборкой имеется в виду сборка проекта для конечного пользователя, по-другому *бандлинг*.

1. Сборка и сжатие пакета `minecraft-data` (далее: mcdata):
    1. Инъекция дополнительного кода в код пакета (напрямую). Этот код подменяет все прямые импорты (`require(X)`) на функцию `getData(X)`, а также обновляет пути. Код функции getData() находится в файле `/src/launcher/_mcdata-provider.cjs:importVersionData()`.
    2. Минификация JSON-файлов данных mcdata (ликвидация отступов и пробелов)
    3. Gzip-сжатие
    4. Перемещение их в (/build/)`/repository/game-versions/`.
2. Сборка `mcversions-index.json`.
  > Это набор всех *теоретически* поддерживаемых в данный момент версий (включая Bedrock Edition). Создан для уменьшения I/O задержек (полностью повторяет список названий папок версий из `game-versions`)
3. TypeScript-компиляция MCA Core в `/dist/core/`.
4. TypeScript-компиляция MCA Skills Collection в `/dist/skills/`.
  > Обратить внимание: Коллекция навыков зависит от деклараций типов (typings) MCA Core. ((В будущем, декларации типов будут выделены в отдельный пакет, и возможно опубликованы на NPM))
5. ESBuild-сборка каждого из навыков Skills Collection в единый файл в `/dist/skills_flat/*`
6. Формирование папки `/build/`:
    - `repository/`
      - `game-versions/`  -- (уже сформировано)
    - `skills/`  \<— `/dist/skills_flat/`
    - `program/`
      - ...Launcher  \<— `/src/launcher/program/*` (как есть)
      - `mcversions-index.json`
      - `package.json`  \<— `/package.json`
    - `README.md`  \<— `/Release_README.md`
    - `LICENSE`  \<— `/LICENSE`
7. ESBuild-сборка MCA Core в единый файл. Путь: `/build/program/mca-bundle.cjs`
8. Откат инъекций в библиотеку `minecraft-data`
