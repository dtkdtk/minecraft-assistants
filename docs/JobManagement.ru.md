# Обработка единиц работы

Единица работы представляет из себя объект, самостоятельно хранящий состояние текущей задачи
и реализующий методы взаимодействия с задачей:
- `prepare (ac): Promise<boolean(isActual?)>`
- `execute (ac): Promise<boolean(isCompleted?)>`
- `finalize (): Promise<void>`
- (а также) `handleError (err): void | Promise<void>`

Аргумент `ac` - это коллбэк для проверки актуальности выполнения данной задачи (не остановлено ли оно?):
- `isActual: () => boolean`

При потери актуальности задачи выполняется `finalize()`, но эта задача
НЕ удаляется из очереди. Значение, возвращённое prepare/execute, игнорируется.

> Примечание: Далее, аргументы методов (такие как `ac` и `err`) и их типы будут опущены.


## 1. Основные методы

- `prepare()`: Выполняется перед началом выполнения основной части работ (execute()).
Это происходит перед изначальным началом выполнения и после каждого снятия задачи с паузы.
Если возвращает `true`, тело задачи выполняется как и ожидалось.
Если возвращает `false`, задача считается выполненной (или неактуальной)
и удаляется из очереди (с вызовом finalize()).
- `execute()`: Тело задачи. Если промис разрешается в `true`, это означает, что задача
была окончательно выполнена, и должна быть убрана из очереди задач (с вызовом finalize()).
Если возвращает `false`, задача выполняется X раз до того момента, пока промис
не разрешится в `true` (либо задача самостоятельно не выйдет из очереди).
- `finalize()`: Выполняется перед окончательным завершением выполнения задачи
И перед постановкой задачи на паузу.
- `handleError()`: Обрабатывает ошибки (исключения), возникшие в процессе выполнения
любого из этапов выполнения задачи. По умолчанию, ошибка логируется и репортится,
а задача удаляется из очереди.


## 2. Стандартный порядок выполнения задачи

1. Вызов `await prepare()`. Если возвращается `false`, задача удаляется из очереди.
2. Вызов `await execute()` до тех пор, пока не вернётся `true`.
3. Вызов `await finalize()`


## 3. Механизм прерываний

Если в процессе выполнения задачи "A" в очереди задач появилась другая, более приоритетная
задача "B", то задача "A" *ставится на паузу*, после чего начинается выполнение задачи "B".
После окончательного выполнения задачи "B", будет продолжено выполнение задачи "A".

1. Постановка задачи "A" на паузу:
  1. Вызов `await finalize()`
  2. Примечание: 
2. Выполнение приоритетной задачи "B" в стандартном режиме.
3. Выполнение задачи "A" в стандартном режиме. (с сохранением состояния)
  1. Вызов `await prepare()`. Если возвращается `false`, задача удаляется из очереди.
  2. Вызов `await execute()` до тех пор, пока не вернётся `true`.
  3. Вызов `await finalize()`


### Тонкости поведения и рекомендации

> [!IMPORTANT]\
> Выполнение `await execute()`, уже начавшееся, прервать на произвольном моменте невозможно.
> Метод `execute()` должен в процессе своего выполнения **самостоятельно** проверять,
> актуальна ли выполняемая задача (с помощью коллбэка `isActual`).
> Это следует делать между долгими шагами (promises / тяжёлые вычисления / тайм-ауты).
> Вызов `finalize()` происходит **раньше**, чем `execute()` закончит своё выполнение. Поэтому,
> ответственность за правильное прерывание (и очистку побочных эффектов) лежит на `finalize()`.

При прерывании, результат выполнения текущего прерываемого шага
(`await prepare/execute()`) будет проигнорирован.

Прерывание выполнения задачи внутри `finalize()` и любой из стадий `execute()`
должно быть максимально быстрым (до `50` мс). Это рекомендация.

Если метод `execute()` постоянно возвращает `false` ((более 1000 раз за секунду)),
это будет расценено как бесконечный цикл, и будет выкинуто исключение `InfiniteLoopDetected`,
которое, как и любая другая ошибка выполнения задачи, будет передана в `handleError()`.


## 4. Обратное управление очередью

Навыкам (и их задачам) доступны следующие методы управления очередью задач:
- `add (job)`: Добавить задачу в очередь.
- `terminate (jobRef)`: Завершить работу (с вызовом `jobRef.finalize()`).
Примечание: Нужно обладать оригинальной ссылкой на объект работы, чтобы удалить его.
- `exists (jobRef)`: Проверить, существует ли указанная задача в очереди.
Примечание: Нужно обладать оригинальной ссылкой на объект работы, чтобы проверить его.


## 5. Обработка ошибок при исполнении задачи

Если в процессе выполнения любого из этапов было выкинуто исключение (ошибка), то:
1. **Задача удаляется из очереди.**
2. Ошибка отлавливается и передаётся в `handleError()`.
Если задачу следует повторить - обработчик ошибок (handleError)
должен самостоятельно добавить задачу в очередь.
3. Выполняется метод `finalize()` удалённой задачи.
